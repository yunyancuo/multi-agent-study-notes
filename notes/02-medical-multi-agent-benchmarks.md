# 02 医疗多智能体决策与模拟问诊评测（MDAgents、AgentClinic 与医院仿真）

医疗与听力学临床决策兼具“多模态客观检查”与“患者主观诉求”两类输入，且容错率极低。本篇笔记梳理 2024 至 2026 年医疗多智能体领域的代表性工作（MIT 的 MDAgents、Johns Hopkins 与 Stanford 的 AgentClinic、清华大学的 Agent Hospital），并结合我们与同事协作开展的“模拟医生问诊评测”总结接口联调经验。

## 一、 论文精读：MDAgents 医疗复杂度自适应编排

* **来源**：Yubin Kim et al. (MIT Media Lab), *MDAgents: An Adaptive Collaboration of LLMs for Medical Decision-Making*, NeurIPS 2024 (arXiv:2404.15155) 及 2025 年后续临床推理基准测试。
* **核心问题**：静态的多智能体辩论（Static Multi-Agent Debate）在简单病例上浪费算力且容易引入幻觉干扰；而在复杂多模态病例上，单一 Agent 又难以兼顾影像、电生理与临床病史。
* **核心机制（三级自适应路由）**：
  1. **复杂度评估（Complexity Check）**：由顶层 Moderator（对应本课题的 A0 总控 Agent）先对输入病例的模态数量、指标冲突程度与临床风险进行分级。
  2. **低复杂度路由**：常规标准病例直接分配给单个初级临床 Agent（PCC）快速处理，避免多 Agent 通信开销。
  3. **高复杂度路由（MDT 会诊模式）**：当不同检查模态结论冲突或涉及疑难病变时，动态拉起多学科团队（MDT），并通过 Moderator 汇总各方证据链；若多轮讨论无法达成共识，强制引入外部临床指南检索或升级至人类医生。
* **2025 至 2026 年后续研究的警示（从众偏见与错误放大）**：
  近期多项医疗多智能体实证研究表明，缺乏证据锚定的自由辩论会导致“从众偏见（Conformity Bias）”：持有正确小众诊断的专科 Agent 往往在多轮对话中被多数派 Agent 说服。因此，**冲突仲裁不能靠投票表决，必须依据预设的证据可靠性等级（Evidence Hierarchy）进行裁定**。

## 二、 论文精读：AgentClinic 与 Agent Hospital 模拟问诊基准

* **来源 1**：Samuel Schmidgall et al. (Johns Hopkins / Stanford), *AgentClinic: A Multimodal Agent Benchmark to Evaluate AI in Simulated Clinical Environments*, arXiv:2405.07960, 2024/2025.
* **来源 2**：Junkai Li et al. (Tsinghua University), *Agent Hospital: A Simulacrum of Hospital with Evolvable Medical Agents*, arXiv:2405.02957, 2024/2025.

### 1. 静态题库与动态问诊的巨大落差
传统医疗评测（如 MedQA）将所有检查结果一次性塞入 Prompt 让模型做选择题；而在真实门诊中，患者最初只能提供模糊主诉，医生必须通过多轮追问并按需开具检查单才能逐步拼齐诊断依据。AgentClinic 实验表明，当从静态问答切换为多轮主动问诊时，主流大模型的诊断准确率出现显著下滑。

### 2. AgentClinic 的四角色解耦架构
1. **Patient Agent（患者智能体）**：持有底层真实病历与主观感受（含认知偏差或表达不清），仅在医生追问到对应维度时才披露信息。
2. **Doctor Agent（被测医生智能体）**：负责多轮问诊、决定开具哪些检查（如纯音测听、声导抗、耳镜），并最终给出诊断与干预方案。
3. **Measurement Agent（检查设备智能体）**：拦截医生开具的检查请求，返回对应的结构化指标或图像特征。
4. **Moderator / Judge Agent（裁判与评估智能体）**：判定问诊是否遗漏关键红线问题，并将医生最终方案与临床金标准对比打分。

## 三、 本课题实践：模拟医生问诊评测协作与审核验配 Agent 联调

在课题组与同事合作开展的“模拟医生问诊评测”项目中，我们将上述 AgentClinic 架构与本课题已有的听力学专职模块进行了工程融合。我方核心承担**后端开放接口（API）建设、暑期审核验配 Agent 接入以及跨模块适配支撑**。

### 1. 跨系统接口的数据对齐（非结构化对话 → 结构化听力学 Schema）
同事负责的模拟问诊端输出的是多轮医患自然语言对话记录及初步提取的患者诉求，而我方暑期开发的“审核验配 Agent”以及 AI 验配 V5 需要严格定长的听力学结构化特征。在联调适配中，接口层完成了三项标准化处理：
* **频点与侧别规范化**：将问诊中零散提及的纯音听阈（250Hz 至 8000Hz 气导/骨导）、PTA 均值、气骨导差统一对齐到左耳（`L`）与右耳（`R`）独立对象。
* **患者画像枚举映射**：将自然语言描述的“手脚不太灵便”“以前戴过模拟机觉得吵”映射为标准枚举字段（操作能力等级、既往使用经验、声学场景需求）。
* **缺失字段显式标记**：对问诊未覆盖的检查项标记为 `null` 或 `uncollected`，禁止接口层擅自填充默认值，交由下游审核模块判定该缺失是否触发阻断。

### 2. “先审核、后验配”的双阶段服务链路
模拟问诊评测系统调用我方 API 时，后端内部按严格先后顺序执行两个阶段：
1. **第一阶段：档案完整性与听力学逻辑审核**
   * 检查必填项：核查左右耳侧别是否明确、核心言语频段（500Hz、1000Hz、2000Hz、4000Hz）听阈是否齐全。
   * 交叉逻辑核验：例如当气骨导差大于等于 15dB 时，核查问诊是否补充了声导抗（鼓室图）或中耳病变排查；若存在急性中耳炎、突发性耳聋等临床禁忌症，直接返回“阻断验配、建议转诊耳鼻喉科”的审核结论。
2. **第二阶段：AI 验配 V5 方案生成与白盒解释**
   * 对于通过审核的病例，调用 AI 验配 V5 文件交换接口与规则筛选引擎，生成目标频响增益配置与推荐助听器类别。
   * 同步输出基于听力学原理的参数解释文本，返回给模拟问诊评测端，作为评估被测 Doctor Agent 验配方案质量的参考基准（Oracle）。
