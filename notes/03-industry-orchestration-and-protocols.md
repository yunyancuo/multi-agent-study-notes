# 03 工业界多智能体编排实践与协议栈（Anthropic、OpenAI、MCP 与 A2A）

除学术论文外，2025 至 2026 年各大 AI 实验室与开源社区在生产环境落地多智能体系统时，公布了一系列极具参考价值的工程复盘与通信协议标准。本篇笔记重点拆解 Anthropic 多智能体研究系统工程报告、OpenAI Agents SDK 演进、以及 MCP 与 A2A 双层协议栈。

## 一、 Anthropic 工程报告：主从式多智能体系统的生产级经验

* **信源**：Anthropic Engineering Blog, *How we built our multi-agent research system*, 2025年6月.
* **架构模式（Orchestrator-Worker 主从编排）**：
  Anthropic 放弃了早期的扁平对等群聊模式，采用严格的 **Lead Agent（总控） + Parallel Subagents（并行子智能体） + Verification/Citation Agent（后置核验）** 架构。
* **核心量化指标与工程教训**：
  1. **性能收益与 Token 成本的权衡**：在复杂多源信息整合评测（BrowseComp）中，多智能体架构比单智能体（Claude Opus 4）准确率高出 **90.2%**；但多智能体系统的平均 Token 消耗是普通单轮对话的 **15 倍** 左右。因此，简单、线性的子任务严禁滥用多 Agent 群聊，必须由总控按需调度。
  2. **外部化状态存储（Externalized Memory）**：长链路多智能体运行极易撑爆上下文窗口。Anthropic 的做法是让总控 Agent 在规划阶段立即将当前任务状态、患者/用户标识与阶段计划写入外部持久化存储（Memory / State Store），即使上下文截断或重启，也能通过读取状态快照继续执行。
  3. **委派指令的四要素（Delegation Contract）**：总控在调用子 Agent 时，若只给一句模糊指令，子 Agent 极易重复劳动或跑偏。每次委派必须显式包含四项内容：明确的目标、预期的输出 Schema、允许调用的工具/数据源范围、以及硬性任务边界（什么事不要做）。
  4. **面向 Agent 的工具人体工学（Tool Ergonomics）**：工具报错信息若只返回笼统的 `500 Error` 或格式错误，会导致 Agent 盲目重试。将工具返回改造为包含具体缺失字段名与修复提示的结构化报错后，整体任务耗时下降了 **40%**。
  5. **断点恢复（Checkpoint Resumption）**：生产环境中的多智能体长任务随时可能因单个子接口超时而中断。系统必须在每个子 Agent 完成节点落盘保存快照，支持从失败节点原地重试或续跑，而非从头重跑整条链路。

## 二、 OpenAI Agents SDK 与主流框架的收敛趋势（2025至2026）

* **信源**：OpenAI 正式发布生产级开源框架 **OpenAI Agents SDK**（2025年3月，演进自早期实验项目 Swarm），以及 LangGraph 1.0、Microsoft AutoGen v0.4（AG2）架构重构。
* **工业界框架收敛出的四项最小原语**：
  2025 年以后，工业界普遍抛弃了过度复杂的拟人化角色扮演封装，收敛为四个核心工程组件：
  1. **Agents（专职推理单元）**：绑定特定指令、工具集与强制输出结构（Structured Outputs / Pydantic Schema）的模型实例。
  2. **Handoffs（显式控制权交接）**：将“转交另一个 Agent”建模为一次类型安全的函数调用，交接时只传递清洗后的结构化状态摘要，而非把长达数万字的原始聊天记录原样倾倒给下游。
  3. **Guardrails（并行/前置护栏）**：在进入高成本推理或下游写操作之前，使用轻量级规则或小模型并行执行输入输出合规检查（如侧别核对、越界参数拦截），一旦触发红线立即熔断（阻断保护）。
  4. **Tracing（全链路可观测与留痕）**：自动记录每次 Agent 调用、工具入参出参、Handoff 路由原因与耗时，供事后审计与评测回放。

## 三、 2025至2026 协议标准：MCP 与 A2A 的垂直与水平分工

当前多智能体工程生态已形成清晰的“双协议栈”格局，直接对应本课题架构图中 **SKILL** 与 **Agent** 的区分：

| 维度 | MCP（Model Context Protocol） | A2A（Agent2Agent Protocol） |
| :--- | :--- | :--- |
| **主导与推出时间** | Anthropic 发起（2024.11），2025 年获 OpenAI/Google/微软全面接入 | Google 联合 50+ 企业发布（2025.04） |
| **连接方向** | **垂直连接（Agent → Tool / Skill / Data）** | **水平连接（Agent ↔ Agent）** |
| **调用对象特征** | 确定性函数、算法脚本、数据库查询、文件读写（无自主多轮意图） | 具备独立状态、多步推理与内部闭环的专职智能体（对调用方黑盒） |
| **核心交互机制** | JSON-RPC 同步工具调用（`tools/call`）与资源读取 | Agent Card 能力发现、Task 生命周期管理、SSE 状态流、Artifact 交付 |
| **本课题对应模块** | **A5 SKILL（AI 修模）**、**A7 AI 验配 SKILL（V5 算法核心）** | **A0 总控 Agent** 与 **A1~A4、A6、A8、A9** 之间的跨模块协同与仲裁 |

### 工程启示：为什么流程图里 A5 和 A7 核心标为 SKILL？
在课题架构图中，**A5（AI 修模）** 接收耳道 3D 模型与款式，计算输出外壳 3D CAD 及三维抽象声学特征（通气孔有无/粗细、出声孔朝向、剩余空间体积）；**A7 中的 AI 验配 V5** 接收特征并输出频响增益参数。这类模块本质上是**输入输出高度确定、内部由专业几何/声学模型驱动的垂直能力**，按 MCP 规范封装为可被 Agent 调用的 **SKILL** 最为干净高效，不需要让它们再去走多轮自然语言寒暄。而外层的参数微调迭代、解释生成（A7b）及问题分流，则由具备上下文判断能力的 **Agent** 承担。
