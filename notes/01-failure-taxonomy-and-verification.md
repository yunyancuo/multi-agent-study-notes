# 01 多智能体失效分类学与裁判验证机制（MAST 与 Agent-as-a-Judge）

多智能体系统在复杂任务重分解上表现突出，但在缺乏结构化约束时，多个大模型串联往往带来更高的错误放大率与 Token 消耗。本篇笔记梳理 2025 年多智能体失效实证研究（MAST）与裁判智能体（Agent-as-a-Judge）的核心结论，并提炼本课题总控 Agent（A0）与审核模块的设计依据。

## 一、 论文精读：为什么多智能体系统会失败？（MAST 分类学）

* **来源**：Mert Cemri et al. (UC Berkeley), *Why Do Multi-Agent LLM Systems Fail?*, arXiv:2503.13657, 2025.
* **研究对象**：作者对 MetaGPT、ChatDev、HyperAgent、AppWorld、AG2（AutoGen）和 Magentic-One 等主流开源多智能体系统的真实运行轨迹（Execution Traces）进行了大规模人工与自动标注。
* **核心发现**：多智能体系统的失败很少单纯源于底层基座模型推理能力不足，绝大多数崩溃来自**编排拓扑缺陷、跨 Agent 上下文丢失以及缺乏硬性验证机制**。

### 1. MAST 三大类 14 项失效模式拆解

UC Berkeley 团队将多智能体失效归纳为以下三类：

1. **规范与系统设计问题（Specification & System Design Issues）**
   * 不遵守角色或任务边界（例如负责评估的 Agent 越权修改了上游输入参数）。
   * 重复执行已完成的步骤，陷入局部死循环。
   * 丢失历史上下文或关键状态标识（例如长链路流转后丢失初始约束）。
   * 缺乏明确的终止条件认知，无法判断何时应当停止迭代或报错退出。
2. **智能体间协同失准（Inter-Agent Misalignment）**
   * 对话状态意外重置，前序 Agent 产出的关键中间结论在交接时被截断。
   * 遇到模糊或缺失输入时不主动发起澄清，而是基于脑补假设继续往下算。
   * 任务偏航（Task Derailment）：多个 Agent 在多轮交互中逐渐偏离最初的用户需求。
   * 信息隐瞒或忽略同级输入：下游 Agent 忽略上游传来的警告标志，强行生成结果。
3. **任务验证与终止缺陷（Task Verification & Termination）**
   * 过早终止（Premature Termination）：在硬性指标尚未全部满足时就宣布任务完成。
   * 表面化验证（Superficial Verification）：验证节点仅检查输出格式合法（如 JSON 可解析），未核查业务数值与物理约束是否自洽。

### 2. 论文中的干预实验结论

作者尝试仅通过优化角色 Prompt（Role Prompting）来修复上述问题，发现改进幅度有限。真正有效的修复手段必须依赖系统层面的硬性工程约束：
* 引入强制 Schema 与状态机校验，取代自由文本对话交接。
* 为每个循环迭代节点设置硬性轮数上限（Hard Iteration Cap）与人工升级通道（Human Escalation）。
* 引入独立于生成模型的验证器（Verifier / Judge），且验证器必须能够调用外部确定性计算工具或规则库。

## 二、 论文精读：从 LLM-as-a-Judge 到 Agent-as-a-Judge

* **来源**：Mingchen Zhuge et al., *Agent-as-a-Judge: Evaluate Agents with Agents*, arXiv:2410.10934, 2024/2025.
* **核心痛点**：传统的 `LLM-as-a-Judge` 仅对最终输出文本打分（Outcome Reward），无法检查多步工作流中的中间动作是否合规。在医疗、工程设计等高风险场景中，即使最终推荐文本看似合理，若中间跳过了禁忌症排查或左右耳侧别核对，结果依然不可用。
* **机制改进**：
  1. **全轨迹审计（Trajectory-level Auditing）**：裁判智能体不仅读取最终结果，还逐步核查中间步骤的工具调用入参、状态转移条件与前置依赖。
  2. **工具增强验证（Tool-Augmented Verification）**：裁判智能体本身挂载确定性校验脚本、领域规则库与数据库查询接口，依靠规则与计算判分，而非仅靠语言模型主观印象打分。

## 三、 对本课题（听力学多模态多 Agent 系统）的工程指导

结合 MAST 失效分类学与 Agent-as-a-Judge 范式，我们在课题架构中落地了以下四项具体机制：

### 1. 统一标识防上下文漂移（针对 MAST 第 1/2 类失效）
在 A1至A9 的跨模块流转中，最常见的工程事故是“左耳听力图配上了右耳 3D 耳道模型”或“参数回滚后版本号错乱”。因此，A0 总控 Agent 强制在所有模块通信请求头中维护全局唯一标识：
* `patient_id`：患者唯一标识。
* `ear_side`：`left` / `right` / `binaural` 显式枚举，严禁缺省。
* `version_id`：记录当前助听器初版方案、修模 CAD 与验配参数的版本链，确保回滚操作可精确定位。

### 2. A7 验配调试的 5 轮硬性上限与 H3 人工兜底（针对 MAST 死循环失效）
在 A7（AI 验配 SKILL + 调试 Agent）内部，每轮执行“仿真验证 → A7b 听力学解释 → 人工确认”。为防止算法在复杂听损构型下无限微调增益曲线，系统设定硬性计数器 `max_iterations = 5`。一旦连续 5 轮仿真验证未达标，A0 立即挂起自动流转并触发 **H3 特例介入**，交由人工听力师接管。

### 3. A8 独立评估与 A0 三路分流仲裁（针对 MAST 表面化验证失效）
生成验配参数的 Agent（A7）不能自己评估自己。架构中专门拆分出 **A8 验配效果评估 Agent**，强制接入外部真耳分析、声场测试、言语测听得分与问卷数据。当评估未通过时，由 A0 结合客观指标将问题明确分流至三条互斥路径：
* **路径① 参数问题**：退回 A7 带反馈条件重算。
* **路径② 物理适配问题**（如胀痛、密封漏音引发啸叫）：退回 A5 重新生成外壳 CAD，避免在硬件外壳不合身的情况下徒劳调整软件增益。
* **路径③ 设备能力不足**：当 A7 重算后发现目标增益超出当前受话器最大输出功率时，直接退回 A6 更换助听器品牌或品类，重走 `H2 → A5 → A7`。

### 4. 暑期审核验配 Agent 的双阶段设计
在已完成的暑期“助听器验配参数智能审核系统”中，采用了与 Agent-as-a-Judge 一致的“规则校验 + 模型解释”双层结构：先通过听力学硬规则核查输入频点完整性、气骨导差阈值与侧别一致性，再对验配参数合理性给出白盒化听力学解释。该模块现已封装为开放 API，直接支撑团队模拟医生问诊评测。
