# 04 听力学多模态多 Agent 系统（A0至A9）总控设计与写作规范

本篇笔记将前序学术论文（MAST、MDAgents、AgentClinic、Agent-as-a-Judge）与工业界实践（Anthropic 主从架构、OpenAI Guardrails/Handoffs、MCP/A2A 协议）转化为本课题 **A0 总控 Agent** 的工程实现规范，并沉淀一套可复用的**多智能体协作写作模式清单**。

## 一、 总控 Agent（A0）的六大控制机制与工程实现设计

在课题架构图中，A0 位于右侧全局管理域，以虚线连接全部核心判断网关。A0 不直接参与具体的听力图识别或声学增益计算，而是作为**全局状态机（State Machine）、质量网关（Guardrail Gateway）与冲突仲裁器（Arbiter）**运行。

### 1. 智能编排（Dynamic Orchestration）
* **设计依据**：借鉴 MDAgents 的按需路由与 Anthropic 的 Lead Agent 任务拆解。
* **实现逻辑**：临床真实患者到店时，往往并非四类检查资料（A1 听力图、A2 耳道 3D、A3 电生理、A4 CT）全部齐全。A0 根据当前已上传资料清单动态生成执行有向图（DAG）：常规成人感音神经性耳聋可仅凭 A1 + A2 启动主链路；婴幼儿或疑似蜗后病变、中耳畸形病例，则强制挂载 A3（ABR/ASSR）与 A4（CT）节点。

### 2. 统一标识（Unified Context Identity）
* **设计依据**：防范 MAST 分类学中的“状态丢失”与“跨节点张冠李戴”。
* **实现逻辑**：A0 为每个会话分配不可变的全局上下文信封（Context Envelope），所有子 Agent 与 Skill 的请求/响应必须携带并校验以下四个字段：
  ```json
  {
    "case_id": "CASE_20261027_001",
    "patient_id": "P_88412",
    "ear_side": "left",
    "version_chain": {
      "recommend_ver": "v1.0",
      "shell_cad_ver": "v1.1",
      "fitting_param_ver": "v1.3"
    }
  }
  ```

### 3. 质量把关与阻断保护（Quality Gate & Hard Circuit Breaker）
* **设计依据**：OpenAI Guardrails 前置熔断机制。
* **实现逻辑**：
  * **H1 前置把关**：A1~A4 采集完成后，A0 自动核查气骨导频点缺失率、左右耳标签一致性及耳道扫描完整度。若核验失败，立即阻断向下游 A6 的流转，转入 **人工复核 H1** 触发补录或重传。
  * **硬性临床阻断**：当识别到急性外耳道炎、活动性中耳积液或不明原因突发耳聋等助听器验配禁忌症时，A0 直接触发阻断保护，中止自动验配流程并提示医疗转诊。

### 4. 冲突仲裁（Evidence-Grounded Conflict Arbitration）
* **设计依据**：克服医疗多智能体中的“从众偏见”，采用证据等级裁定。
* **实现逻辑**：
  * **输入层冲突**：当 A1 纯音测听结果与 A3 电生理（客观阈值）或声导抗出现矛盾时，A0 按临床客观证据优先级触发交叉核对或退回重查。
  * **评估层分流仲裁（A8 之后）**：当患者佩戴后反馈效果不佳时，A0 结合 A8 的客观验证（真耳分析 REM、声场言语得分）与主观问卷，严格裁定问题归属：
    1. **① 参数问题**（外壳佩戴贴合且密封正常，但言语清晰度或响度不适）→ 路由回 **A7** 带反馈条件重算参数。
    2. **② 物理适配问题**（耳道胀痛、通气孔堵耳效应严重、或外壳漏音引发高频啸叫）→ 路由至 **A7 → A5 SKILL**，重新生成外壳 CAD 候选。
    3. **③ 设备能力不足**（经 A7 重算后发现最大声输出或通道压缩能力已达当前机型物理极限）→ 路由至 **A7 → A6**，更换品牌或产品品类，重新走 `H2 医生确认 → A5 修模 → A7 验配`。

### 5. 断点续跑（Checkpoint & Resume）
* **设计依据**：Anthropic 生产级长任务状态快照机制。
* **实现逻辑**：全流程跨越初诊推荐（A6）、医生确认（H2）、3D 修模（A5）、多轮验配（A7）及长期随访（A9），时间跨度可能从几分钟延续至数周。每个节点执行完毕后，A0 将当前状态机节点与中间产物持久化落盘；任何单点超时或人工审批挂起（如等待 H2 医生确认）都不会丢失前置计算结果，确认后直接从断点恢复。

### 6. 全程留痕与三道人工关卡（Audit Trail & Human-in-the-Loop）
* **三道人工关卡**：
  * **H1（数据复核）**：把守多模态原始数据入口质量。
  * **H2（医生确认）**：把守助听器选型与报价方案的临床合规性（支持版本化回滚）。
  * **H3（特例介入）**：当 A7 自动仿真调试迭代达到 **5 轮上限（迭代 ≤ 5 轮）** 仍未收敛时，强制移交资深听力师人工接管。
* **1.11 最终数据闭环输出**：流程收敛并通过 A9 随访确认后，A0 自动打包输出六项资产：特征档案、推荐清单+报价、外壳 CAD、参数版本链、效果报告、审计全集。

## 二、 多智能体协作写作模式优化清单（Prompt & Architecture Checklist）

在编写与迭代多智能体系统时，遵循以下六条工程准则：

1. **先画状态机，再写角色 Prompt**：不要试图用一段几千字的自然语言 Prompt 让单个 Agent 记住整个业务流程图。流程跳转（如 `Y/N` 分支、5 轮上限计数器、三路分流）必须由代码层的状态机（A0）控制，Prompt 只负责当前节点的局部推理。
2. **严禁原始对话历史全量透传**：Agent 之间交接（Handoff）时，上游只向下游传递结构化 JSON 摘要（例如 A5 只向 A7 传递外壳 CAD 路径与通气孔粗细、出声孔朝向、剩余空间体积三项声学特征），不传递内部推理草稿，防止上下文污染。
3. **工具与 Skill 报错必须携带修复指引**：当 A7 文件交换接口或审核接口校验失败时，返回结构中必须指明具体缺失字段名（如 `missing_field: "right_ear.bone_conduction.1000Hz"`）与期望值范围，以便上游问诊或采集节点精准补齐。
4. **生成与解释分离，生成与评估分离**：在 A7 中，底层参数计算（V5 Skill）与面向医生/患者的白盒听力学解释（A7b）分步执行；验配参数生成（A7）与佩戴效果评估（A8）彻底解耦，杜绝“既当运动员又当裁判员”。
5. **所有循环必须配置熔断上界**：任何带反馈重算的环路（如 A7 内部仿真循环、A8→A7 参数重算环路、A9→A7/A8 随访重评估环路）都必须在状态机中绑定最大重试次数与升级出口（H3 或退回 A6 换机型）。
6. **文档与日志坚持平实可审计语域**：Agent 输出的听力学解释（A7b）与审计报告直接面向临床医生与验配师，必须给出具体频点（Hz）、分贝值（dB HL / dB SPL）与声学物理依据，剔除笼统的模棱两可表述。
